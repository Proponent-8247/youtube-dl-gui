# End-to-end review checklist — continuation 9

This continuation records defects discovered while executing the live two-process updater verification required by V011. Findings are committed separately before remediation so failed repair attempts remain reconstructable.

- [ ] **O045 — Bounded updater request blocks the synchronous IPC reply required to complete the handshake**
  - **Priority / state:** High / updater availability; LIVE-E2E-REPRODUCED.
  - **Finding:** The updater begins its live handshake by calling `CopyData.TrySendMessage` for `WM_UPDATEDATAREQUEST`. `TrySendMessage` uses `SendMessageTimeout` with `SMTO_BLOCK | SMTO_ABORTIFHUNG`. The application handles that request by synchronously sending `WM_COPYDATA` back to the updater before returning from `WM_UPDATEDATAREQUEST`. `SMTO_BLOCK` prevents the sending updater UI thread from processing incoming nonqueued messages while `SendMessageTimeout` is outstanding, so the updater cannot process the required reentrant `WM_COPYDATA` response. The request eventually times out and the live updater flow never reaches acceptance, cancellation, replacement, or rollback.
  - **Evidence:** Exact-head Audit verification run `34749841193` at `67aa17f0c5793ab5b8288462411b21e5c399c3c3` builds successfully and passes the existing IPC packet/session tests, but all three real-process V011 scenarios time out waiting for updater completion evidence. `Controls/CopyData.cs` defines `TrySendMessage` with `SMTO_BLOCK | SMTO_ABORTIFHUNG`; `youtube-dl-gui-updater/Forms/frmUpdater.cs::WaitForApplication` uses that helper for `WM_UPDATEDATAREQUEST`; `youtube-dl-gui/Controls/MessageHandler.cs` sends the reply synchronously from inside the request handler.
  - **Repair constraint:** Keep the updater request bounded against a hung/stale application, but allow the updater thread to dispatch the synchronous nested reply required by the existing wire protocol. Do not remove sender/process/window validation or weaken malformed-packet checks.
  - **Acceptance:** The actual Debug application and updater executables must complete all three V011 scenarios: successful Unicode/hash/version exchange and replacement, cancellation with the application preserved, and injected rollback with the prior application restored. Existing forged/wrong-process/malformed-packet and timeout regressions must remain green.

- [ ] **O023 — Documented archive CLI/protocol aliases are not parsed**
  - **Priority / state:** Medium / documented command-line and browser-protocol correctness; SOURCE-CONFIRMED.
  - **Finding:** `ARGUMENTS.md` states that version 3.3.0+ supports video archive aliases `-var`, `-varchive`, `-videoarchive` and audio archive aliases `-aar`, `-aarchive`, `-audioarchive`, and says the `ytdlgui` protocol supports the documented arguments. `Arguments.RetrieveArguments` recognizes none of those aliases. Its only archived case is the undocumented `"archived" or "ar"`, which produces `ArgumentType.DownloadArchived`; there is no parser case for the documented audio-archive aliases or `DownloadArchivedNoSound`. A user/userscript following the repository's argument contract therefore gets no queued download for documented archive invocations.
  - **Evidence:** Root `ARGUMENTS.md`, Video/Audio sections document the six archive aliases. `youtube-dl-gui/Arguments.cs`, `RetrieveArguments`, switch cases include video/audio/auth/custom plus only `case "archived" or "ar"`; `Enums/ArgumentType.cs` contains archived variants that the parser does not map from those documented names.
  - **Audit rationale checkpoint:** The documentation is explicit user-facing compatibility surface and should be treated as intended behavior unless deliberately deprecated. Do not solve this by silently deleting documented aliases. First reconcile which archive modes are actually supported by the current `ytarchive:` implementation, then make parser, protocol forwarding, and help text agree.
  - **Acceptance for patch pass:** Table-test every documented alias with and without the optional leading hyphen and through a `ytdlgui:` invocation; assert the documented video/audio archive behavior is produced, existing ordinary/auth/custom aliases remain unchanged, malformed/missing operands are rejected, and the existing undocumented `archived`/`ar` compatibility behavior is preserved or explicitly deprecated. Add an end-to-end second-instance/protocol case so parsing and dispatch are both covered.

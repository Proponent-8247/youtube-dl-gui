- [ ] **O034 — `ExtendedTextBox.ButtonAlignment` implements Left and Right backwards**
  - **Priority / state:** Low / shared-control contract and Designer correctness; SOURCE-CONFIRMED.
  - **Finding:** The `ButtonAlignment` enum documents `Left` as the left side and `Right` as the right/default side. `ExtendedTextBox.UpdateButton`, however, maps `ButtonAlignment.Right` to X=0 (physical left) and the default/Left case to `ClientSize.Width - InsetButton.Width` (physical right). `Refresh` similarly reserves the left text margin for `Right` and the right margin for the default/Left case. The backing field initializes to `Left` while the property's `[DefaultValue]` says `Right`. Existing application Designer files commonly serialize `ButtonAlignment.Left` for browse buttons that visually appear intended on the right, suggesting they have adapted to the inverted implementation. The public property semantics and serialized design state are therefore inconsistent even if current forms often look correct.
  - **Evidence:** `Controls/Enums/ButtonAlignment.cs` documents `Left`/`Right`. `Controls/ExtendedTextBox.cs`: `fButtonAlignment = ButtonAlignment.Left`; property has `[DefaultValue(ButtonAlignment.Right)]`; `UpdateButton` maps `Right => new(0,-2)` and default to the right edge; `Refresh` maps `Right` to `EC_LEFTMARGIN` and default to `EC_RIGHTMARGIN`. Main/settings/batch/authentication Designer files explicitly store `ButtonAlignment.Left` for their inset-button text boxes.
  - **Audit rationale checkpoint:** Simply correcting the switch would move every currently serialized `Left` button and create a broad UI regression. The patch pass must first distinguish intended visual placement from persisted/designer workaround values, then migrate usages atomically or retain a compatibility shim. This is a shared-control API defect, not justification for unrelated visual refactoring.
  - **Acceptance for patch pass:** Instantiate the control with each enum value at multiple widths/DPI settings; assert physical button position and reserved text margin match the documented side. Inventory every shipping Designer assignment and record intended visual placement before migration. After correction, compare screenshots/coordinates for current forms so browse/action buttons stay where intended, verify resize/handle recreation preserves alignment, and ensure Designer serialization/default behavior no longer flips values unexpectedly.

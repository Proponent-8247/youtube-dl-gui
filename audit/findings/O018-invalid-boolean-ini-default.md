- [ ] **O018 — Malformed boolean INI values ignore the declared fallback default**
  - **Priority / state:** Medium / configuration correctness and recovery; SOURCE-CONFIRMED.
  - **Finding:** `IniProvider.Read(bool Value, bool Default, ...)` returns `true` for `true`/`on`/`1` and returns **false for every other existing string**, instead of returning `Default` when the stored value is not a recognized boolean. Missing keys correctly use `Default`, but malformed/corrupt/hand-edited values do not. This is observable for settings whose default is true, including first-run and multiple download behaviors: an invalid value silently converts the setting to false rather than recovering to its declared default.
  - **Evidence:** `youtube-dl-gui/Config/Interfacing/IniProvider.cs`: the bool overload does `return Data.ToLower() switch { "true" or "on" or "1" => true, _ => false };`. Callers pass true defaults for values such as `Initialization.firstTime`, `Downloads.separateDownloads`, `Downloads.SaveFormatQuality`, `Downloads.VideoDownloadSound`, `Downloads.AutomaticallyDownloadFromProtocol`, `Downloads.SkipUnavailableFragments` and `Downloads.AbortOnError`.
  - **Audit rationale checkpoint:** The API explicitly accepts a `Default` value and the int/Point/Size/Version overloads use it on parse failure. Boolean parsing should have the same recovery semantics. Recognized false spellings can remain false, but unrecognized data should not be conflated with false.
  - **Acceptance for patch pass:** For both `Default=true` and `Default=false`, test missing key, `true`, `on`, `1`, `false`, `off`, `0`, mixed case, whitespace, empty and arbitrary malformed text. Define recognized false spellings explicitly and assert malformed data returns the supplied default. Add startup coverage proving a malformed `firstTime` value does not silently suppress first-run setup, while a valid false still does.

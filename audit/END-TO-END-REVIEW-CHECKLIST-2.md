# End-to-end review checklist — continuation 2

This file continues `audit/FINDINGS-CHECKLIST.md` and `audit/END-TO-END-REVIEW-CHECKLIST.md`. Each newly confirmed issue is committed before review proceeds so interruption leaves a recoverable audit trail. Entries contain concise audit rationale, source evidence, and patch-pass acceptance criteria; they do not contain private chain-of-thought. Production code is not changed in this pass.

- [ ] **O016 — Authenticated download secrets are exposed in child-process command lines**
  - **Priority / state:** Medium / local credential confidentiality; SOURCE-CONFIRMED.
  - **Finding:** Authentication passwords, two-factor values, and media passwords are decrypted and appended directly to the downloader process command line as `--password`, `--twofactor`, and `--video-password`. The application correctly masks these values in its own preview/log strings, but the actual `ProcessStartInfo.Arguments` still contains the plaintext secrets. On Windows, process command lines can be inspected by sufficiently capable local processes (including same-user/debug-capable tooling), and crash/diagnostic tooling can capture them. DPAPI protection of the stored byte arrays therefore does not protect the secret while the downloader child is running.
  - **Evidence:** `youtube-dl-gui/Classes/DataClasses/DownloadInfo.cs`, the legacy included-equivalent argument path in `youtube-dl-gui/Classes/DownloadInfo.cs`, `youtube-dl-gui/Classes/DataClasses/ExtendedMediaDetails.cs`, and `youtube-dl-gui/Classes/DataClasses/YoutubeDlData.cs` each call `Authentication.GetPassword()` / `GetMediaPassword()` and concatenate the returned plaintext into downloader CLI arguments. Download/conversion forms launch those generated strings through `ProcessStartInfo.Arguments`.
  - **Audit rationale checkpoint:** The existing censored preview only protects application logs/UI; it does not change the operating-system-visible command line. The patch pass should use a downloader-supported secret transport that does not place plaintext credentials in argv (for example, a tightly permissioned ephemeral configuration/input mechanism if compatible with all supported providers) and must preserve current authentication functionality. Do not silently remove password-based authentication merely to close this finding.
  - **Acceptance for patch pass:** Run authenticated quick, extended, metadata-probe, batch, and retry flows with controlled credentials containing spaces, quotes, Unicode, and empty optional fields. Inspect the spawned child command line and application logs and assert no password/2FA/media-password plaintext appears. Verify the downloader still receives the exact secret through the replacement mechanism; ephemeral secret material is access-restricted, deleted on success/failure/cancellation, and never reused across unrelated jobs. Document any provider mode for which a non-argv secret channel is impossible rather than weakening authentication silently.

- [ ] **O017 — Diagnostic logging records complete source URLs, including potentially sensitive query/userinfo data**
  - **Priority / state:** Medium / diagnostic-data confidentiality; SOURCE-CONFIRMED.
  - **Finding:** Several normal code paths log the full user/media source string without redaction. `YoutubeDlData` logs complete URLs while gathering metadata, the quick downloader logs `CurrentDownload.DownloadURL`, `Program.ProcessCopyData` logs the URL received over IPC, and extended-downloader error paths include the media URL. For signed URLs, bearer-like query parameters, embedded URI credentials, private share tokens, or other secret-bearing links, those values are retained in the application's diagnostic log/debug output. This is distinct from O016: even if CLI credentials are moved out of argv, a token carried inside the URL can still be disclosed by normal application diagnostics.
  - **Evidence:** `youtube-dl-gui/Classes/DataClasses/YoutubeDlData.cs` logs `URL` before/after metadata retrieval and thumbnail work; `youtube-dl-gui/Forms/frmDownloader.cs` logs `CurrentDownload.DownloadURL`; `youtube-dl-gui/Program.cs` logs `ProcessCopyData called: {Type} > {URL}`; `youtube-dl-gui/Forms/frmExtendedDownloader.cs` includes `Media.URL` in thumbnail/queue failure logging. `Log.Write` forwards the text to the log form and `Debug.Print` unchanged.
  - **Audit rationale checkpoint:** Downloader operands intentionally include arbitrary site URLs and some provider-specific expressions, so logging cannot assume query strings are harmless. Diagnostics should retain enough origin/context to troubleshoot without persisting secrets by default. Raw provider stdout/stderr is a separate diagnostic surface and should be reviewed explicitly rather than claiming one sanitizer covers all third-party output.
  - **Acceptance for patch pass:** Exercise ordinary HTTP(S) URLs, URI userinfo, signed query strings, fragments, local paths, search expressions, and provider-specific pseudo-URLs. Normal logs and copied diagnostic text must not contain secret query values/userinfo while still identifying the host/path or a stable redacted representation. Verify error dialogs and exception extra-info do not reintroduce the raw link. Decide and document how opt-in verbose/raw provider output is handled, rather than silently stripping content users explicitly requested for debugging.

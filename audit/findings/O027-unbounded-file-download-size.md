- [ ] **O027 — File downloads have no total-byte or overall-duration bound**
  - **Priority / state:** Medium / availability and storage exhaustion; SOURCE-CONFIRMED.
  - **Finding:** `ManagedHttpClient.DownloadFileTaskAsync` streams response data to disk until EOF. `WriteStream` enforces a per-read inactivity timeout but has no maximum decoded byte count and no overall transfer deadline. A peer that continuously supplies bytes therefore never triggers the stall timeout and can grow the destination `.tmp` file until storage is exhausted or the user cancels. This file path is used for application/dependency/language downloads. The bounded 32 MiB string/metadata and thumbnail paths do not protect file downloads.
  - **Evidence:** `Controls/ManagedHttpClient.cs`: `DownloadFileTaskAsync` opens the destination and passes the raw/gzip/deflate stream to `WriteStream`; `WriteStream` loops until `ReadAsync` returns 0, incrementing `CurrentProgress`, with only `ReadTimeout.CancelAfter(DefaultTimeout)` around each read. No maximum bytes, expected-size contract, or overall deadline is applied. `Content-Length` is recorded for progress only and can be absent or dishonest.
  - **Audit rationale checkpoint:** A single universal small cap would break legitimate FFmpeg/application payloads, so the repair needs caller-appropriate limits and/or authoritative expected sizes rather than an arbitrary blanket constant. Continuous progress is not sufficient proof that an update endpoint is behaving reasonably. The limit should apply after decompression when content encoding is used so compression cannot bypass it.
  - **Acceptance for patch pass:** Use loopback responses with correct Content-Length, missing length, understated length, chunked endless data, gzip expansion, slow-but-progressing data, and a legitimate maximum-size payload. Assert configured byte/overall limits terminate the transfer, partial temp files are removed/recoverable, prior output remains intact, cancellation still wins, and expected legitimate provider/FFmpeg/application packages fit their documented limits. Where release metadata publishes an expected size, verify it rather than treating it only as progress information.

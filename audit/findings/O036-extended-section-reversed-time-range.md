- [ ] **O036 — Extended downloader emits reversed time ranges without validation**
  - **Priority / state:** Low-Medium / download-section correctness and input validation; SOURCE-CONFIRMED.
  - **Finding:** The extended downloader stores section start/end as independent `Time` values and saves them directly from `tpStartTime`/`tpEndTime`. `ExtendedMediaDetails.GenerateArguments` emits `--download-sections "*START-END"` whenever both have values but never rejects `EndTime < StartTime`. The shared `TimeOffset` type explicitly treats reversed intervals as invalid, so the actual extended-download path bypasses an invariant already represented in the codebase. Users can therefore generate a nonsensical/rejected section request instead of receiving immediate validation feedback.
  - **Evidence:** `Forms/frmExtendedDownloader.cs`, `SaveMediaOptions`, assigns `MediaDetails.StartTime = tpStartTime.Value` and `EndTime = tpEndTime.Value` independently. `Classes/DataClasses/ExtendedMediaDetails.cs` lines around section generation concatenate both values with no comparison. `Controls/TimePicker.cs`, `TimeOffset(Time StartingTime, Time EndingTime)`, throws `ArgumentOutOfRangeException` when `EndingTime < StartingTime`, but `ExtendedMediaDetails` does not use that type/invariant.
  - **Audit rationale checkpoint:** The patch should validate at the user/model boundary and preserve valid open-ended start-only/end-only semantics. Do not silently swap endpoints, since that changes user intent. Equal endpoints need an explicit policy (currently `TimeOffset` permits them) and should be tested against provider behavior before changing that rule.
  - **Acceptance for patch pass:** Exercise start<end, start=end, start>end, start-only, end-only, both zero, fractional milliseconds, and >24-hour values. Reversed input must be rejected or clearly disabled before launching the provider, valid requests must produce unchanged `--download-sections` syntax, and copied/queued media options must preserve the same validation. Include argument-level tests plus a controlled/current-provider parse test for accepted range formats.

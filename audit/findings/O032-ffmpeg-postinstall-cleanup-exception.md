- [ ] **O032 — FFmpeg archive cleanup failure escapes after a successful install**
  - **Priority / state:** Medium / update reliability and UI exception containment; SOURCE-CONFIRMED.
  - **Finding:** `Updater.UpdateFfmpeg` contains extraction and binary-replacement errors inside its retriable exception loop, but after that loop succeeds it calls `File.Delete(FfmpegZipPath)` outside any catch/finally that converts cleanup failure into a nonfatal result. If the ZIP cannot be deleted (for example transient antivirus/indexer lock, access change, read-only attribute, filesystem fault), the new `ffmpeg.exe`/`ffprobe.exe` pair may already be fully installed yet the method throws instead of refreshing paths/returning success. The Settings `btnSettingsRedownloadFfmpeg_Click` caller is an `async void` handler with no catch/finally, so that exception can reach the WinForms synchronization context and leave the button disabled or terminate/report an application error. First-time setup can likewise fail after the actual install completed.
  - **Evidence:** `youtube-dl-gui/Updater/Updater.cs`, `UpdateFfmpeg`: the `do/try/catch` ends before `// Delete the zip file. File.Delete(FfmpegZipPath); Verification.RefreshFFmpegLocation(); return true;`. `Forms/frmSettings.cs`, `btnSettingsRedownloadFfmpeg_Click`, awaits `Updater.UpdateFfmpeg(...)` without exception handling and only re-enables the button after the await returns normally.
  - **Audit rationale checkpoint:** Failure to remove a no-longer-needed archive is not equivalent to failure to install the executable pair. Cleanup should be best-effort/logged (or explicitly retriable) after installation state is known, and UI controls need a `finally` boundary regardless. Do not roll back a verified working pair merely because ZIP deletion failed unless product policy explicitly requires that atomicity.
  - **Acceptance for patch pass:** Fault-inject a deletion denial/lock on `ffmpeg.zip` after successful extraction/replacement. Assert the installed ffmpeg/ffprobe pair remains valid, `Verification.RefreshFFmpegLocation` runs, the Settings UI remains alive and the button is re-enabled, and cleanup failure is surfaced/logged without an unhandled async-void exception. Also test extraction failure, replacement failure, cancellation, successful cleanup, and first-time setup behavior so result semantics remain unambiguous.

- [ ] **O031 — Downloaded language files are installed without verifying the selected repository object**
  - **Priority / state:** Low-Medium / UI-content integrity and supply chain; SOURCE-CONFIRMED.
  - **Finding:** `Updater.GetAvailableLanguages` retrieves GitHub repository-content metadata including each language file's object `sha`, but `frmDownloadLanguage` downloads the selected `download_url` directly into the live `lang` directory and accepts any successful transfer. The source contains a disabled SHA comparison with a comment that the GitHub SHA did not match the locally calculated SHA. As a result, the metadata identifies a specific repository object while the bytes actually installed are never proven to be that object. Language files are data, not executable code, but they control user-visible labels/dialog text and format strings and can therefore mislead users or trigger parsing/formatting failures if corrupted or substituted.
  - **Evidence:** `youtube-dl-gui/Updater/Updater.cs` deserializes `GithubRepoContent` entries from the upstream `Languages` directory. `Forms/frmDownloadLanguage.cs` retains `Content.download_url`, downloads it through `frmGenericDownloadProgress`, and immediately marks success. The commented-out verification block states `The SHA on github doesn't match what I can calculate here`; GitHub's contents `sha` is the Git blob object ID, not simply SHA-1 of raw file bytes.
  - **Audit rationale checkpoint:** This should not be fixed by comparing raw-file SHA-1 to GitHub's blob ID—that is why the old check disagreed. Either fetch/verify the exact contents API object, correctly compute the Git blob object ID (`SHA1("blob " + length + NUL + bytes)`) if that trust model remains acceptable, or use another authoritative digest/signature mechanism. Because translation files are not executable, keep this finding distinct from O019/O020 and avoid overstating it as code execution.
  - **Acceptance for patch pass:** Select a controlled language metadata entry and test exact bytes, modified bytes, truncated file, changed metadata/object ID, malformed INI content, download cancellation, and replacement failure. Assert the live language file is replaced only after content identity passes, the previous valid translation remains on failure, and a bad translation cannot become the active language. Add a regression for correct Git blob-ID calculation if that mechanism is chosen.

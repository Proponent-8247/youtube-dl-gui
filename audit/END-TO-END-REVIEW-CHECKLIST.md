# End-to-end review checklist — continuation

This checklist continues `audit/FINDINGS-CHECKLIST.md` for the full end-to-end pass begun September 9, 2026. Each issue is committed when confirmed so an interruption leaves a recoverable audit trail. Entries record concise audit rationale and evidence, not private chain-of-thought. Production code is not changed in this pass.

- [ ] **O009 — Updater hash mismatch can be overridden and executed**
  - **Priority / state:** High / local update integrity boundary; SOURCE-CONFIRMED.
  - **Finding:** `Updater.BeginUpdate` compares the updater file to the build-pinned `GeneratedUpdaterHash`, but a mismatch only blocks execution when the user answers **No** to a warning. Answering **Yes** continues to `Updater.Start()` with the mismatched executable. Because the expected hash is compiled into the application and the normal embedded resource is supposed to match it exactly, a mismatch is an integrity failure rather than an ordinary compatibility prompt. A local attacker or corrupted on-disk replacement able to alter `youtube-dl-gui-updater.exe` can therefore rely on user approval to cross the application's own integrity check. This does not by itself establish privilege escalation or a remote attack path.
  - **Evidence:** `youtube-dl-gui/Updater/Updater.cs`, `BeginUpdate`: after `CalculateSha256Hash(UpdaterPath) != KnownUpdaterHash`, execution is aborted only when `dlgUpdaterHashNoMatch` returns `DialogResult.No`; otherwise the code proceeds to construct and start the updater process.
  - **Audit rationale checkpoint:** The invariant is stronger than the prompt implies: the updater bytes are embedded in the same build and their SHA-256 is generated during packaging. There is no legitimate alternate updater hash accepted by this code path, so continuing on mismatch defeats the exact check. Preserve the existing user-facing error flow, but fail closed rather than offering an execution override.
  - **Acceptance for patch pass:** Replace the on-disk updater with controlled mismatched bytes and invoke the update path. Assert that no process starts regardless of dialog response, the invalid file is removed or safely replaced from the verified embedded resource, the freshly written resource is re-hashed before execution, and a matching updater still launches. Add a regression that would fail on the current Yes-to-continue behavior.

- [ ] **O010 — ShowUpdateForm tests stale `LastChecked` before selecting the release it just refreshed**
  - **Priority / state:** Medium / update availability correctness; SOURCE-CONFIRMED.
  - **Finding:** When the selected stable/beta cache is empty, `ShowUpdateForm` calls `RefreshRelease(IncludePreReleases)` and immediately tests `LastChecked?.IsNewerVersion`. `RefreshRelease` populates `LastCheckedLatestRelease` or `LastCheckedAllRelease`, not `LastChecked`. `LastChecked` is assigned from the selected cache only *after* that early-return test. On a fresh call, `LastChecked` can be null and the method returns even though the newly fetched selected release is newer. If it contains stale data from the other channel, that stale value controls whether the dialog is shown.
  - **Evidence:** `youtube-dl-gui/Updater/Updater.cs`, `ShowUpdateForm`: the early `if (LastChecked?.IsNewerVersion != true) return;` occurs between `await RefreshRelease(IncludePreReleases)` and `LastChecked = IncludePreReleases ? LastCheckedAllRelease : LastCheckedLatestRelease;`.
  - **Audit rationale checkpoint:** The earlier channel-snapshot correction protects request/cache identity in `CheckForUpdate`, but this separate consumer still dereferences the mutable aggregate before binding it to the refreshed channel. The correct decision must be made from the selected cache produced by the request, not from prior aggregate state.
  - **Acceptance for patch pass:** With all update caches null, return a controlled newer stable release and assert `ShowUpdateForm` reaches the update dialog; repeat for beta. Seed `LastChecked` with the opposite channel and prove it cannot suppress or force the dialog. Also cover an up-to-date response and failed/null refresh. Preserve the stable/beta snapshot across the await.

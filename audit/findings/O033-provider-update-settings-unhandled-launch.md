- [ ] **O033 — Provider internal-updater launch failures escape the Settings async event**
  - **Priority / state:** Medium / UI reliability and update error containment; SOURCE-CONFIRMED.
  - **Finding:** `btnSettingsRedownloadYoutubeDl_Click` is an `async void` WinForms event that disables its button and, when “use youtube-dl's updater” is selected, calls `Updater.UpdateYoutubeDl(true)` without a `try/catch/finally`. The internal updater path constructs a `Process` for the configured provider and calls `Start()` directly. A `Win32Exception`/invalid-start condition (execution denied, corrupt/non-executable file, path race, policy block, etc.) therefore escapes the event through the WinForms synchronization context, and the button re-enable statement is skipped. Other callers such as startup wrap provider update calls in an exception boundary, so Settings has weaker behavior.
  - **Evidence:** `youtube-dl-gui/Forms/frmSettings.cs`, `btnSettingsRedownloadYoutubeDl_Click`: button is disabled before the internal/external branches and re-enabled only at the bottom; no `try/finally` surrounds the body. `Updater/Updater.cs`, `UpdateYoutubeDl(true)`: after existence check it calls `UpdateYoutubeDl.Start(); return true;` without converting process-start exceptions into the bool result.
  - **Audit rationale checkpoint:** This finding is about exception ownership, not whether provider self-update should remain supported. UI event handlers must not rely on the child executable always being startable, and control restoration belongs in `finally`. Keep the existing user-visible success/failure semantics where possible; a failed launch should be reported as an update failure rather than an application-level unhandled exception.
  - **Acceptance for patch pass:** Configure a controlled provider that starts successfully, exits immediately, is missing, is access-denied/non-executable, and disappears between verification and `Process.Start`. Exercise the Settings button with internal-updater enabled. Assert every failure is contained/reported, the button is re-enabled, no unobserved UI exception occurs, and normal provider `-U` launch behavior is preserved. Add equivalent exception-boundary coverage for the external-provider branch so future thrown errors cannot regress the handler.

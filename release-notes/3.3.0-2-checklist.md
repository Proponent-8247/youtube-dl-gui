# Release checklist — 3.3.0-2

Release type: **prerelease**  
Release branch: `release/3.3.0-2`  
Audited base: `7283444431e1243d83b86bf54838d22e3048cae9`

## Automated candidate gates

- [ ] Audited base is an ancestor of the exact candidate commit.
- [ ] Source version resolves to `3.3.0-2`.
- [ ] Application file version is `3.3.0.2` and informational/product version is `3.3.0-2` in both source metadata and the built executable.
- [ ] Updater file version is `1.6.0.0` and informational/product version is `1.6.0` in both source metadata and the built executable.
- [ ] Debug solution builds.
- [ ] Release updater builds.
- [ ] Release application builds and packages.
- [ ] Regression harness passes before the full Release build.
- [ ] Regression harness passes after the full Release build.
- [ ] x86 regression pass matches the normal regression inventory.
- [ ] Packaged `youtube-dl-gui.exe` and `youtube-dl-gui.zip` hashes match `Release-hashes.md`.
- [ ] Candidate release body contains exactly one updater-compatible `exe sha256:` line and one `zip sha256:` line.
- [ ] Candidate artifact contains the EXE, ZIP, hash file, manifest, release notes, and publication-ready release body.

## Manual smoke tests before publication

- [ ] Launch the packaged executable on a clean supported Windows environment with .NET Framework 4.7.2 available.
- [ ] Verify first-run provider/tool bootstrap behavior and cancellation/error handling.
- [ ] Perform a normal single-video yt-dlp download.
- [ ] Perform a playlist/channel-style quick download.
- [ ] Exercise the extended downloader on a single media item.
- [ ] Exercise batch-from-file import with both a valid file and an invalid/partially invalid file.
- [ ] Exercise a conversion path requiring FFmpeg.
- [ ] Confirm session-history export works and ordinary queue URLs are redacted.
- [ ] Close the application during tracked work and confirm shutdown coordination behaves as expected.
- [ ] Inspect Windows file properties for expected application/updater versions.
- [ ] Confirm no unexpected dialogs or security warnings occur beyond normal unsigned-binary/SmartScreen behavior for an unsigned prerelease.

## Publication preparation

- [ ] Review `release-notes/3.3.0-2.md` for user-facing wording.
- [ ] Use the CI-generated `Release-body.md`; do not manually retype hashes.
- [ ] Mark GitHub release as **prerelease**.
- [ ] Tag must be exactly `3.3.0-2`.
- [ ] Tag/target commit must be the exact release-approved commit.
- [ ] Attach `youtube-dl-gui.exe` and `youtube-dl-gui.zip` with those exact names.
- [ ] Verify the release-body EXE SHA-256 matches the attached executable after upload.
- [ ] Verify the ZIP SHA-256 matches the attached archive after upload.
- [ ] Explicitly acknowledge that this prerelease does **not** establish the fork's stable update channel: `/releases/latest` remains unavailable until a non-prerelease fork release exists.
- [ ] Decide the stable-channel plan before calling the fork's release infrastructure production-ready (normally a later stable version such as the post-preview `3.3.0`, after its own release validation).
- [ ] Merge the approved release-prep changes into `master` or otherwise ensure the release tag is reachable from the maintained release history before considering the release closed.

## Post-publication checks

- [ ] GitHub API `/releases` exposes `3.3.0-2` as a prerelease.
- [ ] A beta-enabled application sees `3.3.0-2` through the fork release feed.
- [ ] Confirm `/releases/latest` still does not expose this prerelease; stable-only clients must not receive it as a stable update.
- [ ] Direct asset URLs for `youtube-dl-gui.exe` and `youtube-dl-gui.zip` return the published artifacts.
- [ ] Recalculate both public assets' SHA-256 values and compare with the release body.
- [ ] Preserve the final release commit, workflow run IDs, artifact hashes, and smoke-test result in the release record.

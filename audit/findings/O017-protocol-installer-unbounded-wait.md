- [ ] **O017 — Protocol installer can block the Settings UI indefinitely**
  - **Priority / state:** Medium / availability and UI responsiveness; SOURCE-CONFIRMED.
  - **Finding:** When the application is not already elevated, `frmSettings.btnSettingsDownloadsInstallProtocol_Click` starts the same executable with `Verb = "runas"` and then calls parameterless `InstallerProcess.WaitForExit()` synchronously on the Settings UI thread. Any child that starts but does not terminate (hung registry operation, unusual elevation/session behavior, or a fault in the `installprotocol` path) freezes the Settings form indefinitely. Only UAC cancellation before successful start is handled.
  - **Evidence:** `youtube-dl-gui/Forms/frmSettings.cs`, `btnSettingsDownloadsInstallProtocol_Click`: `InstallerProcess.Start(); InstallerProcess.WaitForExit(); Result = InstallerProcess.ExitCode;` executes directly in the event handler with no timeout/cancellation and no background await.
  - **Audit rationale checkpoint:** Installing the protocol is expected to be a short foreground operation, but that does not justify an unbounded UI-thread wait on another process. The intended elevation and exit-code contract can be preserved while waiting asynchronously and bounding/handling a stalled child. Do not kill an unrelated process; ownership is clear because this child was started by the form.
  - **Acceptance for patch pass:** Replace the installer path with a fixture that exits 0, exits 1/2, delays then exits, and hangs. Verify the UI message loop remains responsive, normal exit codes preserve current behavior, UAC cancellation remains handled, and a hung child reaches a defined timeout/cancel path without leaving an orphaned owned helper. Exercise form closure while waiting.

# End-to-end review checklist — continuation 6

This file continues the prior end-to-end audit checklists. Findings are committed individually for interruption-safe recovery. Production source is unchanged in this review pass.

- [ ] **O035 — External language strings used as composite formats are not validated before later `string.Format` calls**
  - **Priority / state:** Low-to-Medium / localization robustness; SOURCE-CONFIRMED.
  - **Finding:** The language loader validates/parses the INI structure inside a catch/fallback boundary, but it assigns external values verbatim to properties that are later treated as .NET composite-format strings. Examples include `GenericAltError`, `dlgUpateYoutubeDlNoUpdateRequired`, `lbAboutBody`, `frmExtendedDownloaderRetrieving`, `lbUpdateAvailableCurrentVersion`, `lbUpdateAvailableUpdateVersion`, `lbUpdateSize`, and the updater's `dlgUpdaterUpdatedVersionHashNoMatch`. There is no validation that braces are balanced or that placeholder indices are compatible with the number of arguments each call site supplies. A syntactically valid language file can therefore load successfully and later cause `FormatException` from ordinary UI actions by supplying text such as `{`, `{2}`, or malformed format items. Because the exception occurs after `LoadLanguage` has returned, its existing catch/fallback-to-English path does not contain the failure.
  - **Evidence:** `Controls/Extensions.cs` implements `.Format(...)` as a direct `string.Format(str, objs)`. Main application call sites format translator-controlled values in `frmSettings`, `frmDownloader`, `frmAbout`, `frmExtendedDownloader`, and `Updater/Form/frmUpdateAvailable`. `youtube-dl-gui-updater/Forms/frmUpdater.cs` directly calls `string.Format(Language.dlgUpdaterUpdatedVersionHashNoMatch, ExpectedHash, ReceivedHash)`. Both language loaders assign matching external keys without validating composite-format grammar/arity.
  - **Audit rationale checkpoint:** Translators need freedom to reorder placeholders, so a patch must not require the exact English ordering or literal text. The invariant is only that each externally supplied format string is syntactically valid and refers only to placeholder indices that the corresponding call contract supplies. Invalid translations should fall back to the internal-English value for that key (or another explicitly documented safe behavior) rather than crashing a later operation.
  - **Acceptance for patch pass:** Load real main/updater language files plus controlled values with reordered valid placeholders, repeated placeholders, escaped braces (`{{`/`}}`), missing optional placeholders, out-of-range indices, negative/invalid indices, unmatched braces, alignment/format specifiers, and Unicode text. Every normal UI/update call site that consumes a format-bearing language key must either format successfully or use a safe fallback; no `FormatException` may escape after language loading. Preserve translator-supported argument reordering and missing-key English fallback.

- [ ] **O036 — Misc Tools audio actions expose FFmpeg startup failures as application-level UI exceptions**
  - **Priority / state:** Low-to-Medium / shipping tool fault containment; SOURCE-CONFIRMED.
  - **Finding:** The normal Tools > Misc Tools form always exposes Remove Audio and Extract Audio. Neither action checks `Verification.FfmpegAvailable` nor contains `Process.Start` failures. They construct a process using `Verification.FFmpegPath ?? "ffmpeg"` and call `ffmpeg.Start()` directly from the UI event. The application explicitly supports running without FFmpeg (first-run installation can be declined and the configured binary can later disappear), so when no configured/PATH executable is launchable these ordinary buttons can raise a startup exception into global UI exception handling instead of producing a local “FFmpeg unavailable/start failed” result. This is separate from O006, which tracks cancellation/lifetime/cleanup of the Video-to-GIF workflow after conversion begins.
  - **Evidence:** `youtube-dl-gui/Forms/frmMain.cs` exposes `mMiscTools` without an FFmpeg availability guard. `youtube-dl-gui/Forms/frmMiscTools.cs`, `btnMiscToolsRemoveAudio_Click` and `btnMiscToolsExtractAudio_Click`, each build `new ProcessStartInfo(Verification.FFmpegPath ?? "ffmpeg")` and call `ffmpeg.Start()` with no `try/catch` or preflight. The form itself does not disable those controls based on `Verification.FfmpegAvailable`.
  - **Audit rationale checkpoint:** Preserve the lightweight external-console behavior of these tools if that is intentional; the defect is only the uncontained launch boundary. Missing/stale FFmpeg should be detected/refreshed and reported locally, and other startup failures (bad executable, access denied) should not escape the event handler or be mistaken for successful tool execution.
  - **Acceptance for patch pass:** Exercise both actions with a valid configured FFmpeg, FFmpeg found only on PATH, no FFmpeg, a stale configured path, access-denied/non-executable fixture, and a process that starts then exits with failure. The UI must not emit an unhandled exception on startup failure, must not create/claim an output when launch never occurred, and must retain current argument quoting/output naming for successful starts. Verify Video-to-GIF behavior remains governed by its separate lifecycle finding rather than being accidentally changed by this fix.

- [ ] **O037 — Shared `ExtendedTextBox` Ctrl+V validation does not contain Windows clipboard contention**
  - **Priority / state:** Low / shared-control input robustness; SOURCE-CONFIRMED residual of clipboard-contention family.
  - **Finding:** `ExtendedTextBox.OnKeyDown` validates Ctrl+V against the control's allowed-character policy by calling `Clipboard.ContainsText()` and `Clipboard.GetText()` directly for alphabetic/alphanumeric/numeric controls. Windows clipboard APIs can throw `ExternalException` when another process temporarily owns/locks the clipboard. Other application surfaces already catch this condition, but this shared control has no exception boundary, so pressing Ctrl+V at the wrong moment can surface the global application exception UI from any shipping form using these constrained text boxes. This is a residual call site, not a claim that the historical clipboard fixes were wholly ineffective.
  - **Evidence:** `Controls/ExtendedTextBox.cs`, `OnKeyDown`, Ctrl+V branches call `Clipboard.ContainsText()` and `Regex.IsMatch(Clipboard.GetText(), ...)` without `try/catch`. `frmMain.txtUrl_MouseEnter`, clipboard clearing, and other repaired paths explicitly catch `ExternalException`, demonstrating the application's existing policy for a busy clipboard. `ExtendedTextBox` is shared by normal application forms rather than being Debug-only.
  - **Audit rationale checkpoint:** Keep the paste character-filtering semantics. A transient clipboard-read failure should simply suppress/defer the paste or produce a local benign result; it should not relax allowed-character validation and should not become an application-level error. Avoid retry loops on the UI thread.
  - **Acceptance for patch pass:** With a controlled process holding the clipboard open, trigger Ctrl+V in representative numeric, alphabetical, alphanumeric, and unrestricted `ExtendedTextBox` instances across shipping forms. No global/unhandled exception may appear and disallowed data must never bypass validation. After contention ends, normal Unicode/ASCII paste behavior, AllowSpace semantics, Ctrl+A/C/X, and keyboard filtering must remain unchanged.

- [ ] **O029 — Converter applies an incompatible video profile to uppercase `.WMV` outputs**
  - **Priority / state:** Medium / conversion correctness; SOURCE- AND TOOL-CONFIRMED.
  - **Finding:** Standard conversion intentionally suppresses `-profile:v ...` when the output filename ends in lowercase `.wmv`, because the automatic WMV encoder does not accept the H.264-style profile values used by `ConvertHelper`. The guard uses case-sensitive `string.EndsWith(".wmv")`. A user selecting or typing an uppercase/mixed-case `.WMV` output therefore receives the profile flag and FFmpeg rejects the conversion. File-extension classification elsewhere is case-insensitive, so casing should not change conversion semantics.
  - **Evidence:** `youtube-dl-gui/Forms/frmConverter.cs`, argument generation: `if (!CurrentConversion.OutputFile.EndsWith(".wmv") && CurrentConversion.VideoUseProfile) ArgumentsBuffer.Add(...)`. Controlled FFmpeg 7.1.5 execution with `-profile:v high` and a `.WMV` output failed with `Unable to parse option value "high"` / `Error applying encoder options: Invalid argument`; the source guard avoids that flag only for exact lowercase `.wmv`.
  - **Audit rationale checkpoint:** This is a narrow casing defect, not a reason to redesign codec selection. The existing lowercase special case defines intended behavior. The correction should perform an ordinal case-insensitive extension comparison (preferably on `Path.GetExtension`) and retain profile behavior for formats that currently receive it.
  - **Acceptance for patch pass:** Generate and execute equivalent conversions to `.wmv`, `.WMV`, and mixed-case `.WmV` with `VideoUseProfile=true`; all WMV casings must omit the incompatible profile and behave identically. Verify `.mp4`/other profile-supporting outputs still receive the selected profile, extensionless paths remain handled, and full-custom arguments are unchanged. Include argument-level and controlled-FFmpeg regressions.

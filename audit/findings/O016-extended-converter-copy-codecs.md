- [ ] **O016 — Extended converter allows stream-copy to override requested re-encoding options**
  - **Priority / state:** Medium correctness, Release-hidden experimental UI; SOURCE-CONFIRMED.
  - **Finding:** `frmExtendedConverter.SaveMediaOptions` independently saves `CopyCodecs` and the video/audio quality, preset, profile and sample-rate controls; the UI does not make these options mutually exclusive. `ExtendedConversionDetails.GenerateArguments` then emits the requested re-encoding options and later appends global `-c copy`. FFmpeg stream-copy does not perform video/audio re-encoding, so bitrate/CRF/preset/profile/sample-rate requests in this combination are ineffective or can make the command invalid. The older `GenerateArgumentsTest` path avoids some of this by branching on `CopyCodecs`, but the form invokes `GenerateArguments`, not that test routine.
  - **Evidence:** `youtube-dl-gui/Forms/frmExtendedConverter.cs` saves `CopyCodecs`, `VideoBitrate`/`VideoCRF`, preset/profile, `AudioBitrate`/VBR and sample rate independently. `youtube-dl-gui/Classes/DataClasses/ExtendedConversionDetails.cs` emits those options and then, in the Misc region, adds `-c copy` whenever `CopyCodecs` is true. No `chkCopyCodecs` change handler disables or clears the encoding controls.
  - **Audit rationale checkpoint:** “Copy codecs” and “re-encode with these parameters” are contradictory operation modes for the same streams. The patch should define precedence explicitly rather than rely on FFmpeg option ordering. Because this UI is currently hidden from normal Release use, fix it without promoting the experimental converter to a supported feature.
  - **Acceptance for patch pass:** Exercise CopyCodecs alone and in combination with CRF, video bitrate, preset, profile, audio bitrate/VBR and sample rate. Verify the UI and generated command agree on whether affected streams are copied or encoded. Also test mixed intent if supported (for example copy video while re-encoding audio); otherwise reject/disable contradictory combinations before launch. Use a controlled FFmpeg fixture or command inspection and keep existing stream-selection behavior intact.

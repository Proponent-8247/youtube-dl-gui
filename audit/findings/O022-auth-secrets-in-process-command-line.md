- [ ] **O022 — Authentication secrets are exposed in downloader process command lines and retained argument strings**
  - **Priority / state:** Medium / credential confidentiality; SOURCE-CONFIRMED.
  - **Finding:** `AuthenticationDetails` stores password bytes with CurrentUser DPAPI, but every authenticated argument-generation path calls `GetPassword()`/`GetMediaPassword()` and concatenates the resulting plaintext into `--password`, `--twofactor`, and `--video-password` command-line arguments. Those strings are then assigned to `ProcessStartInfo.Arguments`. On Windows, command lines can be inspected by other processes with sufficient same-session/user rights and commonly appear in diagnostics/process-management tooling. The generated argument/model strings also retain plaintext longer than the transient decrypted byte buffer. The separate `PreviewArguments`/`ProtectedArguments` masks only UI/log presentation and does not protect the actual child command line.
  - **Evidence:** `youtube-dl-gui/Classes/DataClasses/DownloadInfo.cs` and `Classes/DataClasses/ExtendedMediaDetails.cs` append decrypted credentials to the real argument buffer while adding `***` only to preview/protected output; `Classes/DataClasses/YoutubeDlData.cs` does the same for metadata probes. `frmDownloader`/`frmExtendedDownloader` pass those real strings to `ProcessStartInfo.Arguments`. Historical plaintext-buffer clearing does not remove these immutable strings.
  - **Audit rationale checkpoint:** DPAPI-at-rest protection is undermined if the normal execution path republishes secrets through a globally inspectable process attribute. A repair must respect what each supported downloader actually accepts: prefer a secure non-command-line credential channel when available (for example a tightly ACLed transient config/input mechanism), minimize plaintext lifetime, and never silently break provider authentication. Administrator/debugger access cannot be eliminated, but routine command-line disclosure should not be necessary.
  - **Acceptance for patch pass:** Launch an authenticated controlled provider fixture and inspect its Windows command line from a separate same-user process; assert password, two-factor value, and media password are absent while authentication still reaches the provider through the chosen supported mechanism. Verify temporary credential material has restrictive ACLs, is uniquely named, is deleted on success/failure/cancellation/crash-recovery where possible, and is not logged. Cover quick download, extended download, metadata retrieval, username-only/netrc/cookies paths, spaces/quotes/Unicode, and provider compatibility. Document any provider that cannot avoid command-line credentials as an explicit residual risk.

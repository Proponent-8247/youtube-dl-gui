- [ ] **O028 — Shipping “Download subtitles” feature has an empty download action**
  - **Priority / state:** Medium / user-visible functional correctness; SOURCE-CONFIRMED.
  - **Finding:** The main application's Tools menu exposes `mDownloadSubtitles`, whose click handler opens `frmSubtitles` modally in normal application code. The subtitle form lets the user enter/select a URL and language choices and displays a **Download** button, but `btnSubtitlesDownload_Click` has an empty method body. Clicking the advertised download action therefore performs no download, reports no error, and leaves the user with a silently nonfunctional shipping feature. This is distinct from the explicitly Release-hidden extended-converter UI.
  - **Evidence:** `youtube-dl-gui/Forms/frmMain.cs`: `mDownloadSubtitles_Click` constructs `frmSubtitles` and calls `ShowDialog()`. `Forms/frmMain.Designer.cs` includes the menu item in the Tools menu without a Debug-only guard. `Forms/frmSubtitles.cs`: `btnSubtitlesDownload_Click(object sender, EventArgs e) { }` is empty even though the form documents the intended yt-dlp/youtube-dl subtitle options in its source comments.
  - **Audit rationale checkpoint:** A visible command whose primary action is a no-op is a correctness defect, not a request to cosmetically complete every unfinished tool. The patch pass first needs to confirm intended subtitle semantics (manual vs automatic subtitles, selected languages, format, output location) from the existing controls/comments and upstream behavior; alternatively, if the feature is intentionally unfinished, it should not be exposed in Release until implemented.
  - **Acceptance for patch pass:** In a Release build, open Tools -> Download subtitles and test a controlled provider fixture for one language, multiple languages, `all`, no subtitles, automatic subtitles where intended, malformed URL, provider failure, cancellation, and output placement. Assert the Download action constructs the documented provider arguments, provides progress/error feedback, does not download the media body when subtitle-only behavior is intended, and never remains a silent no-op. If product policy chooses to hide the unfinished feature instead, add a Release UI test proving it is not exposed while preserving any Debug-only development route.
